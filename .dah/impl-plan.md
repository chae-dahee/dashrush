# DashRush 구현 순서 계획

`plan.html`의 설계를 구현하는 순서를 정한다. 단계는 17장 로드맵(0~4단계, MVP까지)을 따르며, 각 단계는 앞 단계의 완료 기준을 충족한 뒤 시작한다. 혼자 달리는 단계를 멀티플레이보다 먼저 두는 이유는 조작감을 동기화 문제와 섞기 전에 따로 다듬기 위해서다. 물리를 `packages/shared`에 두므로 1단계의 로컬 주행 코드가 3단계에서 그대로 클라이언트 예측 코드가 된다.

## 0. 뼈대

모노레포와 인증·연결 경로를 먼저 세운다. 이후 모든 단계가 이 경로 위에서 동작하므로, 화면보다 연결을 먼저 확인한다.

- pnpm 워크스페이스와 `packages/shared`, `apps/server`, `apps/web`을 구성한다.
- shared에 클라이언트→서버, 서버→클라이언트 이벤트 맵 타입을 정의하고 Socket.IO 서버·클라이언트에 제네릭으로 연결한다.
- Hono로 `POST /api/guest`(닉네임 검증, JWT를 `HttpOnly; Secure; SameSite=Lax` 쿠키로 발급)와 `GET /api/health`를 만든다.
- Socket.IO 연결 미들웨어에서 쿠키의 토큰을 검증하고 사용자 ID와 닉네임을 소켓 데이터에 넣는다.
- 웹과 서버를 같은 도메인으로 서비스하도록 Vite 개발 프록시를 설정한다.
- 클라이언트 소켓 싱글턴을 만들고 `time:ping`/`time:pong`으로 시계 동기화와 핑 표시를 구현한다.

완료 기준: 닉네임 입력 후 소켓이 연결되고 핑이 표시된다.

## 1. 로컬 주행

서버 없이 브라우저에서 혼자 달리며 조작감을 다듬는다.

- shared에 맵 JSON 형식, 타일 문자 대응표, 맵 검증 함수를 만들고 오벌 맵을 작성한다.
- shared에 입력 비트 정의와 1 tick 물리 순수 함수(노면, 회전, 가속, 측면 접지, 벽 충돌, 부스트 패드, 드리프트 게이지)를 만든다.
- shared에 체크포인트 선분 교차 판정과 진행도 계산을 만든다.
- web에 Three.js 경주 화면(바닥 텍스처, 벽 상자, 저폴리 카트), 30Hz 고정 tick 루프, 키보드 입력, 랩·기록 HUD를 만든다.
- 3인칭 추적 카메라를 기본으로 두고 `V` 키로 1인칭과 전환한다. 시점 뷰를 보완하는 미니맵을 HUD에 둔다.
- 초기 상수(6장 표)로 시작해 직접 달려 보며 조정한다.

완료 기준: 혼자 오벌을 3랩 돌고 기록이 나온다.

## 2. 멀티플레이

서버 판정 구조를 세우고 다른 카트를 보이게 한다. 이 단계에서는 내 카트도 예측 없이 서버 스냅샷으로 그려도 된다.

- 서버에 방 객체, “방 코드 → 방”, “사용자 ID → 현재 방” Map, 방 코드 발급을 만든다.
- 방 상태 머신(waiting → countdown → racing → results → waiting)과 `room:create`, `room:join`, `room:leave`, `room:config`, `room:start`, `room:state`, `room:error`를 구현한다.
- racing 상태에서만 도는 accumulator 방식 30Hz tick 루프, 플레이어별 입력 큐, `race:input`, `race:snapshot`을 구현한다.
- web에 로비, 방 대기(맵 선택, 초대 링크), 서버 시각 기준 카운트다운, 다른 카트 100ms 지연 보간을 만든다.

완료 기준: 두 브라우저에서 같은 방에 들어가 서로의 카트가 부드럽게 보인다.

## 3. 판정 완성

조작 즉시성과 판정 일치를 완성한다. 검증에 지연 환경이 필요하므로 서버 송수신 경로에 인위적 지연을 넣는 개발용 옵션을 먼저 만든다.

- 내 카트 예측, 미확인 입력 재적용, 화면 오프셋 보정을 구현한다.
- 서버에 카트 간 원 충돌을 구현한다.
- 실시간 순위, 완주 시각 보정, 첫 완주 후 20초 제한, DNF, `race:finish`, `race:result`, 결과 화면, 10초 뒤 자동 재대결을 구현한다.
- 입력 검증(형식, sequence, 큐 상한, 초당 이벤트 제한, 방장 권한)을 구현한다.

완료 기준: 인위적 지연 150ms에서도 조작이 즉각적이고 충돌이 일치한다.

## 4. MVP 마감

남은 기능을 붙이고 실제 기기 조합으로 검증한다.

- 빠른 매칭(공개 방 자동 배정, 맵 무작위, 20초 시작 타이머)을 구현한다.
- 팀전(팀 배정과 `room:team`, 인원 조건, 점수 합산, 팀 색, 팀 점수 HUD)을 구현한다.
- 봇(shared의 입력 비트 생성 함수, `room:bot`, 서버 tick 루프의 봇 입력 공급, 방장 승계·해산 조건에서 봇 제외)을 구현한다.
- 끊김 유예 15초, 고스트 처리, 재접속 전체 상태 복구, `player:disconnected`·`player:reconnected`를 구현한다.
- 도심 서킷 맵을 추가한다.
- 터치 조작(왼쪽 하단 가속·브레이크·드리프트, 오른쪽 하단 좌·우)을 구현한다.
- 효과, 사운드, localStorage 개인 최고 기록, 방 안 누적 전적을 붙인다.

완료 기준: 8명이 휴대폰과 PC를 섞어 끝까지 한 판을 마친다.

## 단계 밖에서 정할 것

`plan.html` 18장의 남은 결정 중 배포 환경과 지역은 4단계 검증 전에 정해야 한다. 렌더링은 Three.js 3D 시점으로 확정했으며, 4단계 전까지는 상자·원기둥으로 만든 임시 모형으로 개발한다.
